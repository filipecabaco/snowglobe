Docs

snowglobe runs a Docker image where Docker isn't. It turns the image into a site, a folder of static files you can host anywhere. Open it in a browser tab, run it from one binary with no Docker installed, or give it to an agent as a sandbox. It starts in about a second, because it restores a snapshot taken once your app was ready.

Getting started

Build a site from a Dockerfile, preview it, then put the folder on any static host.

What you need

  • Docker, or nothing. With Docker, snowglobe builds your Dockerfile and boots it in a build container. Without Docker, --builder native builds from an image in a registry or a saved archive. snowglobe run --runtime native, bundles and snowglobe mcp need no Docker either.
  • An arm64 Alpine image. Use FROM alpine (multi-arch; snowglobe builds it for arm64) or FROM arm64v8/alpine.
  • On an x86 host, QEMU's binfmt handlers, so Docker can build arm64 images. Docker Desktop has them. On Linux, run this once: docker run --privileged --rm tonistiigi/binfmt --install arm64.

Install

One line installs the latest release into ~/.local/bin. It works on Linux (x86-64 or arm64) and on a Mac with Apple silicon. It checks the download against the release's checksums and needs no sudo. You can read the script first.

curl -fsSL https://filipecabaco.github.io/snowglobe/install.sh | sh

SNOWGLOBE_VERSION=0.4.0 picks a version. SNOWGLOBE_INSTALL_DIR picks another directory.

You can also download a binary from the releases, or install with Go 1.27 or later:

go install github.com/filipecabaco/snowglobe/cmd/snowglobe@latest

Your first site

Any directory with a Dockerfile, or any image reference, builds into dist/:

snowglobe build ./my-app          # a directory with a Dockerfile, or an image reference
snowglobe serve dist              # preview at http://localhost:8000

The page shows a terminal running whatever the image runs: its ENTRYPOINT and CMD, with its ENV and WORKDIR.

dist/ is plain static files. Upload it to GitHub Pages, a CDN or any web server. There is no snowglobe server.

Everything runs on an emulated 64-bit ARM CPU, translated to WebAssembly as it runs, so expect it to be slower than native. Cold loads take seconds. Commands take tens of milliseconds to a few seconds.

What the first build downloads

  • The tools image, the machine that boots and snapshots your image, from ghcr.io/filipecabaco/snowglobe-tools. A version that hasn't been released compiles it locally instead, once, in a few minutes.
  • snowglobe-vm, the machine that runs sites natively. A release of snowglobe is one file that carries its own and unpacks it into your cache the first time it runs a site natively. Built with go install, snowglobe downloads the release's instead.
  • The prebuilt kernel, once, when you build without Docker.

Releases are for Linux on x86-64 and arm64, and macOS on Apple silicon.
